# 交接记录 2026-10-20（Claude）

本轮改动基于 fork 提交 `305e9ca` 的 `obsa-rust/`，逐项开发、逐项完整回归后一并发布。

## 方法

此前工作只用本地模拟服务验证线协议，无法发现与真实 OBS 的不一致。本次把官方华为 OBS Java SDK
源码（`huaweicloud-sdk-java-obs`）和参考实现 `obsa-hdfs` 当作线协议的依据逐项对照，并优先使用
Hadoop 官方契约测试（seek/positioned read、vectored read）而非自写断言。

## 改动

| 改动 | 内容 |
|------|------|
| 定位读取 | 原生 `read(long, byte[], int, int)`：不加锁、不移动游标、大请求并发分块；常驻块快路径 |
| **V2 签名修复** | 签名改用实际发送的百分号编码路径（SDK 签 `uri.getRawPath()`）；子资源改为白名单（官方文档 + SDK 列表），LIST 参数与 `folder` 不再签名 |
| **PFS 自动识别修复** | 同时识别 `x-obs-fs-file-interface: Enabled`（SDK `getBucketFSStatus` 与参考实现使用的唯一信号） |
| 向量化读取 | Hadoop 3.3.5+ `readVectored`：合并相邻范围、跨范围并发、EOF 范围单独失败；官方向量化契约 34 项 |
| 祖先探测减负 | 普通桶：不存在的路径不探测祖先、祖先并发探测；可选 `fs.obs.ancestor.directory.hints` 缓存已证实的隐式目录 |
| AccessLabel xattr | PFS `?x-obs-accesslabel` PUT/GET/DELETE，线格式对照 SDK |
| 凭证刷新 | `fs.obs.credentials.provider`（BasicSessionCredential）与无密钥时的 `fs.obs.security.provider`（SDK IObsCredentialsProvider，反射）按间隔刷新并推送 Rust；参考实现只在初始化读取前者 |
| 服务端加密 | `fs.obs.server-side-encryption-type/key`：SSE-KMS 与 SSE-C 请求头对照 SDK，携带范围对照参考实现；配置错误时初始化报错（参考实现静默不加密） |
| Linux 构建 | 首次 Linux（WSL Ubuntu 22.04）完整回归；修复 fork 共享 flock 导致的上传日志锁偶发冲突；`scripts/build-linux.sh --glibc 2.17` 产出兼容 CentOS 7 / EulerOS 的 .so（见 `LINUX_BUILD.md`） |
| S3 兼容模式 | `fs.obs.signature.type=v2`；对独立 S3 服务端 S3Proxy 验证（Hadoop 契约 135 项 0 失败），修复空 body PUT/POST 缺 `Content-Length`（见 `LIVE_S3_TESTING.md`） |
| getFileChecksum | 服务端整文件 CRC32C（`x-obs-checksum-crc32c`）→ COMPOSITE-CRC32C；无 CRC、目录、前缀长度返回 null（参考实现返回 -1 占位值，会让 distcp 误判相同） |

各项设计与边界见 `POSITIONED_VECTORED_READ.md`、`OBJECT_KEY_PATH.md`（末节）、`ANCESTOR_PROBES.md`、
`API_COVERAGE.md` 第 6、27、28 项。

## 需要维护者决定 / 真实环境验证的事项

1. **PFS mkdirs 的 `?folder` 参数**：规格要求 `PUT key/?folder`，但官方文档的签名子资源列表和 SDK
   都没有 `folder`，SDK 的 `newFolder` 实际发送不带查询参数的 `PUT key/`。
   现在保留发送 `?folder` 但不再签名它。需在真实 PFS 上确认：保留、或改为 SDK 的形式。
   **2026-10-21 维护者决定：暂时保留 `?folder`，待其在真实 PFS 上验证后再定。**
2. 签名与 PFS 识别两项修复依据 SDK 源码，强烈建议首个真实环境冒烟就覆盖：中文/空格/`+` 文件名的
   读写列删、`fs.obs.bucket.mode=auto` 下的 PFS 桶。
3. `fs.obs.ancestor.directory.hints` 默认关闭，因为既有测试明确要求缓存后也立即识别带外文件祖先；
   若可接受 1 s（TTL）陈旧窗口，开启后同目录元数据请求可大幅减少。
4. 此前记录的 JNI 排队内存优化实验未在本次处理。
5. SSE-C 开启时普通桶 HEAD 一律携带客户密钥（与参考实现一致）。若桶中有非 SSE-C 写入的对象（如控制台创建的目录），
   OBS 可能拒绝带 SSE-C 头的 HEAD；需在真实加密桶上确认。
6. 向量化读在 Rust 缓冲、Java 数组、调用方 ByteBuffer 间各复制一次（正确性无碍，大范围有额外内存与复制开销）；
   定位读/向量化读与同步读一样不经过全局预读闸门，只受连接池与缓冲预算（默认关闭）约束。
