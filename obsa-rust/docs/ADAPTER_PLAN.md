## 本轮完成：先阻断数据一致性和凭据接入缺口

1. **普通对象读取固定 ETag。** `fs.rs` 从已有 HEAD/LIST 状态传入 ETag；若没有，从首次 GET 获取。`io/input.rs` 在前台 GET、预读和 seek 后复用同一修订标识。`store/obs.rs` 发送 If-Match，并检查响应 ETag；412、不匹配、缺失版本不会静默切换数据。检测失败后流持续报错并清理预读。
2. **缺失 ETag 默认失败。** `fs.obs.read.change.detection.enabled=true` 默认开启；仅在明确接受无版本保障时设为 false。PFS 是可变文件语义，本轮不对其承诺快照读取，也不强加普通桶策略。
3. **Hadoop 凭据提供器。** Java 适配层通过 `Configuration.getPassword()` 解析通用及桶级 AK/SK/token，遵守 Hadoop 的明文回退开关；临时字符数组清理。Rust Debug 不再打印密钥、令牌或可能含密钥的配置覆盖项。JSON/JNI 传参仍包含必要的凭据，不能声称实现全内存清零。
4. **验证。** 内存测试覆盖同长度覆盖、缓存状态到首次 GET 的竞态、预读、seek、缺失版本和 PFS 分界；HTTP 测试覆盖条件头、412 不重试及服务端忽略条件；真实 JVM 经过 JNI 验证覆盖时抛 IOException；隔离的 Hadoop user:// 凭据提供器验证优先级和明文回退。

ETag 只是修订标识，不被当作内容 MD5。相同 ETag 的变更、无版本历史的服务端行为及远端强一致性不在本轮保证范围。读保护也不能解决 rename 的 copy/delete 原子性。

## 2026-09-27：标准契约、传输限额与复制结果校验

已接入官方契约与分页模拟，并修复首轮失败。JNI 读路径减少一个 Java 数组及一次数组复制，写路径按 1 MiB 分批；HTTP 接收限额覆盖 Content-Length 和 chunked body。特殊名称集成测试进一步发现 CopyObject 源头未编码，现按路径段编码并验证真实请求头。复制和 MPU 完成响应必须是完整成功 XML 且有 ETag；HTTP 200 内嵌错误不会继续执行 rename 的删源阶段。LIST 的截断/错误 XML 及非法大小/分页布尔值也明确失败。

另修复多分块读取在中途失败或取消后逻辑位置前移的问题；未交付的字节不算成功消费，重试恢复到调用起点。Rust 取消注入与 JVM HTTP 失败重试覆盖此边界。

这些改动有局部正确性与分配上限依据，尚未测量新的生产吞吐收益。保留旧 ABI，但新增 Java 适配层需要与新版 native 库配套部署。

下一步：扩展严格异常分类、权限/所有者、并发外部修改和崩溃重启；在目标 Hadoop 发行版以及 Spark/Hive/Flink 上验证，补真实桶运行报告。

验收：记录每个套件的通过、跳过及能力依据；本地模拟和真实桶结果分开。标准测试通过仍不等于完整应用兼容。

### 统一的字节预算与传输限额

现状：新增 HTTP 单响应默认 64 MiB 限额、错误体最多 64 KiB；先验证 206/Content-Range/Content-Length，再使用 Limited 按帧限制 collect，完成后复核字节数。JNI 写入每次暂存不超过 1 MiB 且只复制指定切片；读取直接填充 Java 目标数组，移除临时 Java 数组和二次 arraycopy。旧 nativeRead ABI 保留。

PFS append 已新增按文件系统共享的字节额度（默认 64 MiB），每次复制最多 1 MiB 且先申请额度；任务失败和 drop 可归还额度。直接 Rust 大 write 也会拆分，不再依赖 Java/JNI 限制。取消部分 write 后拒绝继续写入或成功 flush；取消 flush 本身仍可恢复。

可选 fs.obs.buffer.total.bytes（默认 0 关闭）现由真实后端的 HttpPool 与读写流共用。普通上传、append 和 HTTP/范围合并的受控 Vec 按 capacity 计费；扩容计入新旧缓冲共存峰值，Bytes 切片保留整份底层分配租约。HTTP 外部帧按可见长度计费，源帧与合并目标同时计费；进入输入流不重复收费。未知外部容量、Hyper/TLS 内部、元数据和分配器开销仍不在精确统计内，不能当成 RSS 上限。详见 BUFFER_BUDGET.md。

下一步：测量 RSS 与分配开销，继续核对协议构造/JNI 缓冲及传输库内部边界。当前超限返回错误，不等待其他流；公平调度、前台保留额和磁盘 spill 尚未实现。

验收：小内存预算、多流混合读写、慢消费者、异常超长 body、取消/失败后额度归还；记录 RSS 峰值和所有请求/缓冲队列上限。

### 故障恢复与非幂等边界

现状：MPU close 已改为按分片完成顺序处理，发现错误后取消并回收其余任务，保留最初错误；不再让最后提交的卡住请求遮住其他分片的失败。等待 abort 时保留上传 ID，取消 close 或 abort 失败后允许 Drop 做一次清理尝试；Drop 先等待本地分片取消完成。故障注入覆盖阻塞分片、清理中断和清理失败，断言无 complete、额度归还及 abort 次数。

Store 和 HttpPool 现在共用重试次数、状态/错误分类与线性退避策略；Store 每次重新签名，429/500/502/503/504 可重试，501 批量删除直接回退。Hadoop 重试参数与桶级覆盖已接入，显式超过两次的配置不再被静默截断。MPU 初始化/完成与 PFS rename 不自动重试；批量删除校验完整结果和失败项，响应异常不误报成功。单次 HTTP 尝试现共用排队、发送/响应头与响应体期限，超时/取消后的连接额度归还已验证。可选的跨重试 HTTP 总期限已覆盖排队、请求及退避，默认关闭；到期直接退出重试循环，已验证读取取消和连接额度释放。已处理 429 与 Retry-After 秒数/标准日期，取服务器等待与本地退避的较大值，并在等待前释放响应。全局自适应限速、随机退避及整个文件操作的总期限仍未完成。MPU initiate/complete 超时后的远端结果不能靠本地取消确定。运行时/进程退出仍可能中断清理，不能把 best-effort Drop 当作远端无残留保证。

新增可选 fs.obs.upload.journal.dir：取得 MPU ID 后在阻塞工作线程持久化记录，再允许发分片；完成/abort 后移除。命名空间文件锁和活动标记隔离仍在运行的上传。Rust recover_pending_uploads(limit) 显式恢复已知日志，失败保留；损坏记录不发远端请求。同一实例保留目录扫描进度，避免
小批量恢复被开头的保留记录阻挡；取消后保留日志并释放活动标记，后续扫描可重试。子进程绕过 Drop 退出后重新取得锁并恢复的测试已通过，包含 .pending 发布边界。Hadoop 扩展 recoverPendingUploads(limit) 已通过现有 JNI 通道接入，并返回不可变清理报告；恢复逻辑继续由 Rust 负责。另提供 abortUpload(output) 创建流主动放弃扩展，经 JNI 调用 Rust；拒绝追加流和其他实例流。日志初始化、目录扫描、记录读取/解析及删除已移到阻塞工作线程；初始化成功结果由工作线程缓存，等待者取消不丢失结果且失败可重试；删除取消等待后仍持有活动标记与日志锁直到工作结束。详见 UPLOAD_RECOVERY.md。

下一步：继续完善提交结果不确定的错误分类、未取得/未落盘 upload ID 的缺口、真实服务 MPU 生命周期、断电和日志丢失，以及崩溃后的自动调度。当前恢复只 abort 已知 MPU，不重放写入、不扫描全桶。

验收：故障矩阵每项均记录请求次数、远端最终对象状态、临时资源和错误类型，不能只判断抛异常。

## P1：扩展性与大数据工作负载

### 真正分页的目录 API 和有界 copy

现状：已提供按需取页的 Rust ListPager，取消不推进游标，保留协议校验；容量统计已逐页累计并检查溢出，文件条目不再全量保存，但目录集合、marker 历史和跨页重复检测保留的对象键仍随规模增长。`list_all` 基于分页器聚合全部条目；已拒绝同页重复对象键，基于该列表的子对象复制/删除在列表验证通过后继续，正常目录前缀合并保留；Hadoop listStatusIterator 已使用 JNI 游标逐页请求，跨页去重、循环检测及终止错误由 Rust StatusCursor 管理；Java 保留迭代包装和资源回收桥接。EOF/错误/所属 FS 关闭释放原生状态，显式 Closeable 与 PhantomReference 队列处理提前结束；GC 兜底不保证立即释放。Java listStatus JSON 仍全量序列化；普通桶目录 rename 逐项串行 copy。大目录内存与等待时间随条目数增长。

下一步：测量大目录 RSS/首条延迟；为 copy 提供全局及每目录并发额度。读取/复制源版本须固定；禁止把并行 copy 当成解决并发写入下 delete 风险。设计先全量验证或流式变更的失败边界，不能在优化时丢掉已实现的越界检查。

验收：百万条目的 first-result latency、RSS、总请求数；中途取消、权限失败、源变更、目标冲突后对象状态可解释。

### 访问模式与 JNI 成本

现状：固定块预读有利于顺序读取；顺序访问证据改为连续完成的块数，块内重复小 read 不再触发预读；失败/取消时通过检查点同时恢复位置、顺序块数与预读窗口，避免重读重复累计进度；seek 已复用当前缓存块和目标预读的就绪/在途数据，避免丢弃目标请求，其他预读仍取消。列式 footer、小范围随机读仍可能产生下载放大；JNI byte[] 仍有复制，positioned read 复用单流锁。

本地缓存对照支持增加显式 ByteBuffer 读取：大块 direct 路径省去 JNI 临时复制，小块仍保留原 byte[] 路径；见 [JNI 读取对照](JNI_READ_BUFFER.md)。这不是云端吞吐验收。

下一步：借鉴 S3A input policy，区分 sequential/random/adaptive；接入 openFile status hints、vectored ranges 合并、独立 positioned read；补真实作业和有延迟读取对照。

验收：Parquet/ORC 风格访问轨迹、1 B/4 KiB/1 MiB 请求、随机 seek、多线程读取；同时统计有效字节、下载字节、请求数、CPU 与 p50/p95/p99，不只报顺序吞吐。

### 凭据、能力与作业提交

现状：支持初始化时的 Hadoop CredentialProvider；已按原生桶模式暴露 append/truncate capability，并为 append 流声明 hflush/hsync。Rust 凭据快照仍是静态的；没有 STS 刷新、委托令牌、完整 capability 声明、SSE 和作业提交协议。

下一步：可刷新的凭据抽象及过期/刷新并发测试；区分普通桶和 PFS 的 Syncable、append、truncate、rename 保证；验证任务重试和推测执行下的输出提交。普通桶不应假装具备 HDFS 原子 rename。

验收：长任务跨凭据过期、并发刷新只有一次、日志无密钥、重试作业不重复/漏提交；明确列出未支持能力。

## 共享数据预算与显式上传 abort（2026-10-11）

新增 fs.obs.buffer.total.bytes / ObsConfig.buffer_total_bytes，默认 0 关闭，可按桶覆盖。同一文件系统的当前读块、预读、普通上传暂存与请求体、PFS append 请求体共用逻辑数据字节额度。先申请后复制/GET，Bytes 克隆及切片共享租约；预算不足时预读降级，前台返回错误，避免部分持有预算相互等待。写失败持续报错并释放暂存区、取消任务，读失败保持逻辑位置以便释放压力后重试。

新增 Rust ObsOutputStream::abort(self).await，显式丢弃小文件缓冲或取消并等待分片退出后 abort 已知 MPU，不发送 PUT/complete 或调用成功回调。清理失败返回原错误，取消/失败保留 Drop 尽力清理兜底。未知 upload ID、完成响应丢失和进程崩溃后的清理仍未解决。

本轮不把逻辑数据限额当成进程内存上限：分配器空闲容量、Bytes 底层共享分配、HTTP/TLS 暂存、响应合并和元数据没有统一计入。完整作用域、超限行为与本地验收见 BUFFER_BUDGET.md（README 对应 docs/BUFFER_BUDGET.md）。未测新的性能数字。
