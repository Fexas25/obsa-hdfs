# 签名与 HTTP 对象的 Debug 脱敏

2026-10-12。本轮检查本地可验证的诊断输出缺口，修复三个公开类型的 Debug 格式化。没有观察或宣称生产日志已经泄漏；问题是旧版自动派生 Debug 会在调用方格式化对象时输出敏感字段。

## 修复

- SignedRequest：不输出 Authorization、访问密钥、会话令牌及其它头部内容。保留头部数量、日期和脱敏占位符。
- HttpRequest：隐藏完整 URI（包含路径、查询参数）、所有头部内容及请求正文。保留 HTTP 方法、头部数量、可选正文长度和幂等标记。
- HttpResponse：隐藏头部内容及响应正文。保留状态码、头部数量、正文长度、request_id 和 duration_us。

选择仅输出诊断字段，而不是维护敏感头部名称黑名单，避免大小写变体或自定义元数据遗漏。普通 {:?} 和多行 {:#?} 均走同一实现。数据字段仍可按原 API 访问，实际签名、HTTP 请求/响应和正文没有变化。

Debug 不是稳定的序列化协议，依赖旧 Debug 字符串解析数据的调用方需要调整。这里不保证任意调用方自行打印公开字段、错误正文或其它类型时也会脱敏；日期与请求 ID 仍可见，也没有实现全内存清零。

## 本地验证

三个新增回归先在旧实现上运行，全部失败，分别检出签名、请求和响应的受保护数据。修复后 release 三项均通过。测试使用人工标记，涵盖访问密钥、令牌、完整 Authorization、自定义元数据、大小写混合头名、查询参数、路径、请求正文、响应正文和 Cookie；同时确认原始数据仍可正常读取。

完整 Windows Rust workspace 构建及测试：307 通过、0 失败、15 ignored。分项为核心单测 107、缓存测试 1、文件系统测试 153、本地 HTTP 测试 46。JNI crate 构建通过，其 Rust 单测为 0 项，不能把这等同于 JVM 集成验收。本轮未重跑 Hadoop/JVM、诊断特性矩阵、性能基准或真实云服务测试；本轮没有修改这些接口或性能路径，也不宣称吞吐收益。

工作区保留 debug-redaction-before-tests.log、debug-redaction-after-tests.log 和 debug-redaction-full-tests.log。日志、二进制、构建目录及图片不进入 GitHub 提交。
