# 有延迟追加：持续压力与尾延迟

2026-10-11。本轮只补充压力测试和证据，生产代码、FIFO 公平队列、取消实现及默认并发/预算均未修改。

## 测量方法

使用隔离的 range-object 模拟后端、4 个写入流、Tokio 4 工作线程、每请求 4096 字节、每批 16 次 write 后 flush。每个条件持续至少 65 秒，四种并发/预算组合轮换顺序重复三次，共 12 次、约 13 分钟。正式测量使用默认 release 构建，不启用任务诊断探针，不并行运行构建或其它测试。每次包含冷启动，无剔除最慢样本。

配置等待 2 ms，实际等待受本机定时器和调度影响；下文单列实际均值，不能解释成精确 2 ms RTT。后端仅模拟提交前可取消等待和内存定位写入，不覆盖真实网络、HTTP 连接池、服务器限流或网络带宽。

为限制模拟存储增长，每个流每 64 批关闭，逐字节校验后重新创建空对象并从位置 0 开始。单对象预留 4 MiB；替换期间允许新旧分配短暂共存。样本每流最多一百万，超出直接失败。模拟对象和样本内存不属于客户端请求体预算。本测试是多次有限长度流生命周期组成的持续负载，不是单个文件无限追加。

吞吐分母包括创建、关闭、数据校验、重开和最后排空；批次延迟包括 16 次 write 和 flush（含预算/并发等待），不包括生命周期维护。p99 使用全部批次的 nearest-rank 百分位，不能当成单个请求的 p99。每个场景还给出各流统计，原始 JSON 保留每次运行结果；不把三次 p99 再汇总为伪造的合并 p99。本测试为闭环负载，不测开放到达率下排队或纠正 coordinated omission。

每流每 17 批将 flush 单次 poll 后丢弃，若 Pending 计为取消；随后重新 flush，要求所有任务仍能完成。每个对象都校验长度和所有字节，结束时验证延迟调用数等于写入请求数、延迟阶段 active 为零、峰值不超过 min(流数×并发上限,预算/4096)。这覆盖取消 flush 后继续写入，不等于模拟网络错误或进程崩溃。每次还设持续时间加 120 秒的排空 watchdog。

## 结果

下面逐项列出三次吞吐 MiB/s、三次批次 p99 ms、每次样本数，顺序按该条件的运行序号。进度比为每轮最少/最多完成批次数，取三轮最小值；它是饥饿观察指标，不能替代 FIFO 公平性证明。

- 预算 64 MiB，每流并发 4：吞吐 4.002 / 4.022 / 4.022；p99 64.453 / 64.276 / 64.386；样本 4163 / 4186 / 4186；最小进度比 0.9971；实际平均等待的三轮中位数 15.462 ms。
- 预算 64 MiB，每流并发 64：吞吐 16.324 / 16.336 / 16.440；p99 17.281 / 17.232 / 17.438；样本 16983 / 16994 / 17100；最小进度比 0.9963；实际平均等待的三轮中位数 14.904 ms。
- 预算 16 KiB，每流并发 4：吞吐 1.005 / 1.005 / 1.003；p99 266.666 / 267.295 / 267.390；样本 1047 / 1047 / 1045；最小进度比 0.9886；实际平均等待的三轮中位数 15.494 ms。
- 预算 16 KiB，每流并发 64：吞吐 1.001 / 1.005 / 1.004；p99 267.251 / 267.083 / 266.990；样本 1043 / 1047 / 1047；最小进度比 0.9924；实际平均等待的三轮中位数 15.503 ms。

合计完成 1,118,208 个请求、4,139 次 Pending flush 取消，全部数据及计数断言通过。观察到的最大批次耗时为 460.791 ms；本轮没有逐请求分段诊断，不能把尖峰具体归因于锁、调度或服务等待。

三次重复中，宽预算提高并发均增加吞吐并降低批次 p99；紧预算两种并发则几乎相同。这是该闭环模拟负载下的配置对照，不是新旧代码对照。每批只有 16 请求，因此并发上限 64 时每流也最多提供 16 个在途请求，不能把收益解释成用满了 64。各轮最少/最多流进度比均超过 0.988，未观察到明显的流间饥饿；没有对所有调度情况作保证。

低吞吐组每次约 1,040 个批次样本，其 p99 仅由最慢约 11 个样本决定，精度仍有限；每流约 260 个样本的 p99 更不宜用于细小差异判断。此次持续测试不能替代数小时 soak、开放负载或真实云验证。

## 验证与边界

默认 release filesystem 151 项通过、5 ignored；诊断构建 152 项通过、5 ignored。新增 ignored 压力入口另做一秒冒烟和上述 12 次正式运行。原有确定性测试覆盖共享预算排队、取消后保留任务、完成尾任务不丢失前缀等待、追加与连续重命名公平性。本轮压力负载本身没有重命名流，不能声称已完成长时间追加/重命名混合压力验证。

未重跑未变更的 HTTP/JNI/Hadoop 套件，无真实云验证。保持每流默认并发 4、共享请求体预算 64 MiB；测试条件的吞吐差异不是生产代码优化收益。没有依据模拟结果自动调整生产默认值。

## 复现

按项目 Windows 构建脚本准备 MSVC/SDK 环境，再在项目根目录执行。每种配置至少重复三次并轮换顺序；更长 soak 可将 seconds 提高到 3600。worker 范围 1..16，batch 范围 1..64，delay 范围 1..1000 ms；样本达到安全上限则失败，不静默抽样。

```powershell
$env:OBS_APPEND_STRESS_SECONDS='65'
$env:OBS_APPEND_STRESS_WORKERS='4'
$env:OBS_APPEND_STRESS_BATCH='16'
$env:OBS_APPEND_BENCH_DELAY_MS='2'
$env:OBS_APPEND_BENCH_CONCURRENCY='4' # 对照 64
$env:OBS_APPEND_BENCH_TOTAL_BYTES='67108864' # 对照 16384
Remove-Item Env:OBS_APPEND_PROFILE -ErrorAction SilentlyContinue
cargo test --locked --release -p obs-rust-core --test filesystem append_latency::append_sustained::benchmark_append_sustained -- --exact --ignored --nocapture
```
