# 普通桶祖先探测的请求数

2026-10-20。普通桶“文件优先”语义不变：存在文件 `a` 时，`a/b` 在状态、打开、列举、删除、重命名、
元数据等入口均视为不存在。改动只影响为判断这一点所发的请求数和延迟。PFS 不做祖先探测，不受影响。

## 原实现的开销

`get_file_status` 在查缓存之前先调用 `ensure_visible_path`，对每一级祖先**依次**发 HEAD；祖先 HEAD
返回 404（祖先只是目录时的常态）不进入缓存。深度为 d 的路径每次查询都要 d−1 个串行 HEAD，
即使目标状态已在缓存中；不存在的路径同样先探测全部祖先。本地实测：查询 `a/b/c/d/f2` 后再查
已缓存的 `a/b/c/d/f1`，共 9 个 HEAD、8 个串行往返；参考 Java 实现只需 1 个。

## 默认模式（语义与原实现一致）

- 先查目标：只有缓存命中或远端确认存在后才检查祖先。不存在的路径直接返回不存在（被文件祖先
  隐藏的路径与不存在的路径本来就返回同一结果），不再探测祖先，照常写入负缓存。
- 未缓存为目录的祖先**并发**探测，深度 7 的冷查询约 2 个往返而非 7 个。请求数不变。
- 已存在路径每次仍重新探测祖先，所以带外（其他客户端）新建的文件祖先在下一次查询时立即生效，
  既有“缓存后也不能绕过新文件祖先”的 Rust/Hadoop 测试保持原样通过。

## 可选：`fs.obs.ancestor.directory.hints=true`

- 目标确认存在且某祖先不是文件时，该祖先必然是隐式目录，作为目录提示写入缓存（与 LIST 回填
  相同的 `put_directory_hint_if_unchanged`，受失效纪元保护）；负缓存的祖先也视为非文件。
- 深度 5 的文件首次查询 5 个 HEAD，同目录兄弟 1 个，重复查询 0 个（缓存 TTL 内）。
- 代价：带外把已缓存为目录的祖先替换成文件时，隐藏其后代要等元数据缓存 TTL
  （`fs.obs.metadata.cache.ttl`，默认 1000 ms）过期。本实例自己的写操作仍立即失效相关条目。
- 默认关闭，因为原设计明确要求即使在缓存后也立即识别带外文件祖先。

## 验证

新增 Rust 测试：两种模式的请求计数、不存在路径不探测祖先、隐藏语义保持、并发探测时延、
提示模式 TTL 过期后生效、本实例创建文件祖先立即生效。既有两项测试仅把“隐藏键 HEAD 次数为 0”
放宽为“每次操作至多 1 次”（发现文件祖先前可能 HEAD 目标，但从不读取、列举、复制或删除）。
真实 OBS 延迟收益未测。
