# 有延迟的追加与重命名混合压力

2026-10-12。本轮新增测试和诊断证据，没有修改生产调度、公平队列、取消实现或默认配置。

## 负载与计量

4 个追加流，每流配一个重命名任务，持续把同一个文件在 a/b 两个名字之间往返移动。追加调用完整 ObsFileSystem/PfsAppendStream 路径，重命名调用 ObsFileSystem.rename；写入流必须跟随文件移动。每批 16 个 4 KiB 请求后 flush。每 17 批单次 poll flush 后丢弃 Pending future，再次 flush 并继续写入。没有人为取消 write 或提交中的 rename。

每个配置连续至少 65 秒，并发上限 4/64、共享请求体预算 16 KiB/64 MiB，轮换配置顺序重复三次，共约 13 分钟。使用默认 release，Tokio 4 工作线程；构建/回归先完成，基准串行执行，不启用任务诊断特性。没有剔除冷启动或最慢样本。

模拟 append 在提交前异步等待，配置 2 ms，实际受 Windows 定时器和调度影响；JSON 同时记录实际累计等待。重命名本身没有额外模拟网络延迟，但会通过真实客户端协调器等待冲突的在途 append。每次 rename 后 yield_now，不额外 sleep 或限速。因此这是有延迟追加与本地重命名的冲突压力，不是双向网络 RTT 模型，不覆盖目录重命名、覆盖目标、外部客户端或真实云服务。

range-object 后端提供只读取长度的 HEAD 模式，省略可选 ETag，避免每次重命名状态查询重新 MD5 扫描整个文件、以及数据快照造成的写入复制。该模式仅用于本基准；原模式仍保留，新增回归校验创建、追加、重命名前后长度、缺失旧路径与数据。HEAD 不返回伪造的内容校验值。

每流最多写入 64 批（4 MiB）后停止并等待本流 renamer，关闭、核验唯一现存路径的长度与全部字节，再清空对象并重新打开流。其他流继续执行。样本每流每类上限一百万，达到上限失败；对象与样本均不无限增长。这些模拟存储分配不属于客户端请求体预算。总吞吐包含生命周期维护、校验和排空，操作延迟不包含维护。维护窗口暂时暂停对应 renamer，所以并非永不间断的单流 soak。

追加 p99 为 16 次 write 加 flush 的批次延迟，重命名 p99 为一次完整 rename 耗时，均使用 nearest-rank；不是内部锁等待时间。所有负载为闭环，不反映开放到达率排队。5 秒进展窗口按各流启动后的单调时间统计，末尾不完整窗口不用于判断空窗。最长进展间隔包含初次等待及跨 epoch 的维护暂停，记录到最后一次完成；最终排空另受持续时间加 120 秒 watchdog 约束。

## 三次重复结果

以下每行的数值按运行序号列出。追加吞吐 MiB/s、追加和重命名 p99 单位 ms；重命名吞吐单位 ops/s。此外保留最慢单个 renamer 的 p99，防止某个高吞吐任务的短操作掩盖其他任务。

- 预算 64 MiB，并发 4：追加吞吐 3.997 / 3.978 / 3.973；追加 p99 78.091 / 77.956 / 77.931；重命名吞吐 261.217 / 256.398 / 256.951；重命名 p99 16.721 / 16.317 / 16.306；最慢 renamer p99 16.730 / 16.351 / 16.327。追加样本数 4160 / 4139 / 4135。
  三轮最长追加/重命名进展间隔 360.496/314.312 ms；完整 5 秒空窗 0；追加流最少/最多完成批次比最低 0.9961。
- 预算 64 MiB，并发 64：追加吞吐 15.946 / 15.972 / 16.025；追加 p99 30.880 / 30.945 / 30.894；重命名吞吐 281.140 / 268.749 / 269.642；重命名 p99 16.538 / 16.349 / 16.386；最慢 renamer p99 16.553 / 16.370 / 16.397。追加样本数 16588 / 16613 / 16670。
  三轮最长追加/重命名进展间隔 47.519/30.539 ms；完整 5 秒空窗 0；追加流最少/最多完成批次比最低 0.9933。
- 预算 16 KiB，并发 4：追加吞吐 1.009 / 1.011 / 1.009；追加 p99 267.542 / 267.719 / 267.702；重命名吞吐 2097.319 / 1782.289 / 2009.030；重命名 p99 16.072 / 16.101 / 16.084；最慢 renamer p99 16.076 / 16.118 / 16.087。追加样本数 1053 / 1054 / 1052。
  三轮最长追加/重命名进展间隔 270.536/21.483 ms；完整 5 秒空窗 0；追加流最少/最多完成批次比最低 0.9924。
- 预算 16 KiB，并发 64：追加吞吐 1.009 / 1.009 / 1.009；追加 p99 268.475 / 268.310 / 267.233；重命名吞吐 2358.377 / 1850.293 / 1702.948；重命名 p99 16.062 / 16.089 / 16.090；最慢 renamer p99 16.074 / 16.095 / 16.110。追加样本数 1051 / 1051 / 1051。
  三轮最长追加/重命名进展间隔 293.099/61.529 ms；完整 5 秒空窗 0；追加流最少/最多完成批次比最低 0.9924。

共完成 1,097,872 个追加请求、872,228 次重命名、4,059 次 Pending flush 取消。所有运行通过最终长度和数据校验、旧路径消失、调用计数和排空检查。延迟阶段 active 最终为零，峰值不超过 min(流数×并发上限,预算/4096)；这不是进程 RSS 或全部任务生命周期内存上限的测量。

共发现 0 个完整 5 秒无进展窗口。公平性结论需同时结合逐任务 p99、进展间隔和现有确定性测试；不能把有限运行中的无饥饿观察当成任意调度下的证明。重命名突发会明显改变总体吞吐和样本权重，不据此认定生产调度优化成功。

三轮对照均显示，64 MiB 预算下并发 4→64 的追加吞吐约 3.97–4.00→15.95–16.02 MiB/s，批次 p99 约 78→31 ms；16 KiB 预算下两种并发均约 1.01 MiB/s、267–268 ms，没有稳定收益。重命名总体 p99 约 16.1–16.7 ms，最慢任务 p99 也在相近范围；重命名总吞吐的轮间波动较大，不用于调整生产配置。配置等待 2 ms，实际平均等待的逐轮中位约 14.89–15.50 ms。

最长追加/重命名进展间隔仍达到约 360/314 ms，不能凭较低 p99 排除尖峰。紧预算每轮约 1,050 个追加批次，p99 由尾部约 11 个样本决定，每流约 260 个样本的 p99 精度更有限。三次重复不等同于统计置信区间或数小时 soak。

## 验证和保留范围

首次矩阵第二轮遭遇约 500 秒的异常时间跨度，watchdog 失败，并暴露进展桶越界。同期外部等待工具也返回远超请求的等待时长；这支持环境暂停/长时间停顿的可能性，但不能确定原因。修复为末桶记录超界完成，另在 join 后检查最终时长，避免超时已就绪任务绕过检查。新增时钟大幅跳跃的确定性单元测试。保留[首次矩阵日志及二进制 SHA256](benchmarks/append-mixed-interrupted-20261012.json)；修复后的正式矩阵全部重新测量，不混用先前成功结果。

默认 release filesystem 153 通过、6 ignored；诊断构建 154 通过、6 ignored。新增 HEAD 模式回归通过，压力入口另完成一秒紧预算冒烟与 12 次正式运行。原有公平队列、共享预算 FIFO、取消后任务保留、重命名取消等相关回归本轮随 filesystem 套件通过。

保留本地测试后端的可选 HEAD 模式、混合压力入口与证据。生产代码及默认值未变，无真实云验证，未重跑未变更的 HTTP/JNI/Hadoop 套件。本轮各配置之间的差异不是新旧生产代码性能收益。与上轮纯追加结果只能作背景对照，不能作为同期严格 A/B；本轮还改变了 HEAD 模拟和重命名负载。

## 复现

按项目 Windows 构建脚本设置 MSVC/SDK 后，在项目根目录执行。四种组合各重复三次并轮换顺序。seconds 支持 1..3600、workers 支持 1..16、batch 支持 1..64；极长运行可能触及样本上限并明确失败。

```powershell
$env:OBS_APPEND_STRESS_SECONDS='65'
$env:OBS_APPEND_STRESS_WORKERS='4'
$env:OBS_APPEND_STRESS_BATCH='16'
$env:OBS_APPEND_BENCH_DELAY_MS='2'
$env:OBS_APPEND_BENCH_CONCURRENCY='4' # 对照 64
$env:OBS_APPEND_BENCH_TOTAL_BYTES='67108864' # 对照 16384
Remove-Item Env:OBS_APPEND_PROFILE -ErrorAction SilentlyContinue
cargo test --locked --release -p obs-rust-core --test filesystem append_latency::append_mixed::benchmark_append_mixed -- --exact --ignored --nocapture
```
