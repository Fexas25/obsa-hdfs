# 共享缓冲分配预算

更新：2026-10-11。Rust 核心实现，Hadoop 传递配置和错误。

## 配置与共享范围

`fs.obs.buffer.total.bytes`（Rust `ObsConfig.buffer_total_bytes`）默认 `0` 关闭，
支持整数、k/m/g 后缀及 `fs.obs.bucket.BUCKET.buffer.total.bytes`。沿用配置解析规则，
非法值回退默认值。例：`256M` 为 256 MiB 的受控缓冲额度，不是进程 RSS 上限。

真实 OBS 后端由 HttpPool 创建预算，ObsStore、文件系统和它创建的读写/append 流共享。
直接以同一个 ObsStore 构造流也复用该预算。`with_store` 优先采用后端提供的预算；
自定义后端未提供预算时，文件系统创建自己的预算，独立构造的流各自创建预算。
不同 HttpPool 实例之间不共享；不能据此限制整个 JVM。

## 计费与生命周期

- 普通上传暂存区、PFS append 的受控复制，以及 HTTP/范围响应的合并 Vec，按
  `Vec::capacity()` 计费，包含已分配但尚未使用的容量。
- 启用预算时扩容先申请新缓冲的完整容量，复制期间旧缓冲仍保留额度；不会仅计容量差。
  分配器若返回大于请求的 Vec 容量，会在发布数据前补齐额度，否则释放新分配并报错。
- 数据变成 Bytes 后，额度跟随完整底层分配。克隆或切出一小片仍保留整份分配的额度，
  直到最后一个引用释放；不会按切片长度提前归还。
- HTTP 收到的外部 Bytes 帧按可见长度计费。合并时源帧和目标 Vec 同时计费，帧复制后
  及时释放；返回的数据继续携带租约。输入流直接复用已计费的 HTTP 数据，不重复计费。
- 自定义 ObjectStore 未声明预算时，范围收集器负责帧长度和合并分配的计费。
  返回预算的后端必须保证 GET 数据已携带对应租约；这是后端接口约定。

读取替换当前块前释放旧块。GET/预读先检查当前可用额度，随后由收集器申请数据额度，
避免预留额与实际分配双重计费；检查和收到数据之间仍可能遭遇并发竞争。失败、超时或
取消收集释放已持有的租约。PFS append 原有专用字节额度和其他任务数上限继续生效。

## 额度不足时

预读准入失败停止补充预读。前台申请失败返回包含 `shared buffer budget exhausted`
的错误，不等待其他流释放数据，避免多个流各持有部分缓冲而相互等待。
读失败不推进逻辑位置，可在释放压力后重试；写失败持续报错并取消任务，不能原流续写。
异步任务在执行取消、释放最后的数据引用后才归还额度。

预算必须容纳同时存活的源帧、目标缓冲和扩容峰值，不能只按最终文件大小配置。
即使最终数据能放下，扩容峰值不足仍可能失败。增长提示过大时先尝试精确容量；
尚未实现公平排队、磁盘 spill 或前台保留额。普通 MPU 分片最小 5 MiB，预算不足不会
自动更改远端分片协议。极小预算也可能无法容纳 LIST、MPU 或错误响应 XML。

## 验证与边界

本地验证覆盖：未使用容量及切片持有完整分配、扩容峰值和失败后数据保留、多帧 HTTP
合并源/目标共存、取消及延迟响应错误后额度归还、HTTP → 输入流不重复计费、读写共享，
以及普通桶/PFS 的真实 JVM → JNI → 本机模拟服务回归。

Hyper/TLS/内核自身的网络缓冲、外部 Bytes 不可见的底层容量、分配器管理开销、元数据、
协议 XML 构造和调用方/JNI 缓冲不在精确容量统计内。这里约束本实现管理的 Vec 分配容量，
不声称约束所有 malloc 分配或 RSS。原单响应上限和并发限制仍然必要；尚未进行 RSS 压测
或新的性能对比。预算关闭时保留 Vec 原位扩容机会。

主动放弃上传及崩溃后清理见 [上传恢复说明](UPLOAD_RECOVERY.md)。

ByteBuffer 读取的 direct 目标由调用方分配和持有，与 Java 数组同样不计入 Rust 预算。
新路径省去 JNI 临时 Vec，但 HTTP 与范围缓存继续按原规则计费；不是 JVM 内存总量限制。
见 [JNI 读取的所有权与测量边界](JNI_READ_BUFFER.md)。
